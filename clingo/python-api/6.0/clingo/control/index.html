clingo.control ¶

Module containing the Control class responsible for grounding and solving.

Example¶

The example shows the most straightforward way to ground and solve a small test program:

>>> from clingo.core import Library
>>> from clingo.control import Control
>>>
>>> lib = Library()
>>> ctl = Control(lib)
>>> ctl.parse_string("1 { a; b }.")
>>> ctl.ground()
>>> print(ctl.solve(on_model=print))
a
SAT

Ground the given program parts.

Non-ground logic programs must be added before calling this function. Programs can define named sections using #program. directives. These sections can be selectively grounded by specifying their name and binding parameters to symbols.

main ¶

main() -> None

Ground and solve a logic program based on the current control mode.

This function serves as a high-level entry point for the default ground-and-solve process. It considers the current ControlMode and can dispatch execution to a script's main function if defined.

If solving, the function proceeds as follows:

  1. Each set of program parts in parts is grounded sequentially.
  2. After grounding each set, solving is performed immediately.

Before calling main(), the control object can be prepared by parsing programs, registering propagators, or performing other setup steps.

start_solve ¶

start_solve(
    assumptions: Sequence[tuple[Symbol, bool] | int] = [],
    on_model: Callable[[Model], bool | None] | None = None,
    on_unsat: Callable[[Sequence[int]], None] | None = None,
    on_stats: Callable[[Stats, Stats], None] | None = None,
    on_finish: Callable[[SolveResult], None] | None = None,
    yield_: bool = False,
    async_: bool = False,
) -> SolveHandle

Solve the current ground program.

This function runs the solver on the current ground program, optionally using assumptions, callbacks, or asynchronous execution. It returns a SolveHandle, allowing interaction with the solving process.

If asynchronous solving (async_) is enabled, the function returns immediately, and solving runs in the background. Otherwise, the function blocks until solving is complete.

Parameters:

Name Type Description Default
assumptions Sequence[tuple[Symbol, bool] | int]

A list of assumptions that constrain this search. Each assumption is either a tuple[clingo.symbol.Symbol, bool] indicating an atom's truth value or a program literal (see literal). For example, using [(clingo.symbol.Function(lib, "a"), True)] only admits answer sets that contain atom a.

 []
on_model Callable[[Model], bool | None] | None

Optional callback that receives a Model object when a model is found. Returning False from the callback stops solving.

 None
on_unsat Callable[[Sequence[int]], None] | None

Optional callback to intercept lower bounds during optimization.

 None
on_stats Callable[[Stats, Stats], None] | None

Optional callback that receives statistics updates after each step. Two Stats objects are passed: step-specific and accumulated stats.

 None
on_finish Callable[[SolveResult], None] | None

Optional callback called once search has finished. A SolveResult is passed to the callback.

 None
yield_ bool

If True, the returned SolveHandle is iterable, yielding Model objects during solving.

 False
async_ bool

If True, solving runs asynchronously in a separate thread. Note: Callbacks (on_model, on_stats, etc.) will also be called from a separate thread.

 False

Returns: A SolveHandle to control the search.

Notes

Asynchronous solving requires compiling clingo with thread support. Blocking methods on SolveHandle release the GIL but are not thread-safe.

See Also

clingo.solve: Contains examples on using this function.

write_aspif ¶

write_aspif(
    path: str | None = None,
    symbols: bool = False,
    append: bool = False,
    preamble: bool | None = None,
    preprocess: bool = True,
) -> None

Write the current logic programs to the given file.

If append is true, a file will be created if none exists yet. If preamble is None, then the aspif preamble is written for newly created files and omitted for existing files.

If path is None, clingo's internal output buffer is used instead of writing to a file. The buffer content is available via buffer. If preamble is None, the preamble is written only if the buffer is currently empty. In application mode, the buffer is printed to stdout and cleared after each major operation like grounding, so the preamble flag should be set explicitly in this case.

Parameters:

Name Type Description Default
path str | None

The optional path to write the program to.

 None
append bool

Whether to append to an existing file.

 False
preamble bool | None

Whether to write the aspif preamble.

 None
preprocess bool

Whether to preprocess the program before writing.

 True
